# Privacy, Data Retention, License & Koha OPAC Checklist

This checklist audits UEM Kolkata campus pilot readiness across student data privacy, external data processors, source license boundaries, and Koha OPAC freshness / librarian ingestion workflows.

---

## 1. Student Conversation & Research Run Privacy / Retention Checklist

| # | Control / Requirement | Verified Repo State (Code Evidence) | Status | Action Required for Campus GO |
|---|---|---|---|---|
| 1.1 | **Accurate Privacy Notice for Hosted Cloud Stack** | `docs/guides/PRIVACY_POLICY.md` v1.0 states Archipelago is "local-only", "no cloud transmission", and "External LLM APIs... Not used". In reality, hosted `host_inference` uses Supabase cloud PostgreSQL and external LLM APIs (`XKIRO` `api.xkiro.com`, `NVIDIA` `integrate.api.nvidia.com` in `host_inference/engine/llm.py:79-86`). | **FAIL (P1-2)** | Publish a hosted campus privacy notice disclosing Supabase storage, external LLM sub-processors, retention periods, and student rights. |
| 1.2 | **Student Chat Persistence & Telemetry Minimization** | `POST /api/chat` does not persist full conversation transcripts in Supabase, **but** `record_user_action("chat_query", query)` (`routes/chat.py:281`) stores an 80-char scrubbed `detail` snippet in in-memory `_EVENTS` (`deque(maxlen=2000)`, `user_traffic.py:16, 72-97`) and exposes the latest 12 `recent_actions` (including `detail`) to `ELEVATED_ROLES` via `GET /api/analytics/summary` (`analytics.py:286`, `user_traffic.py:160-168`). | **FAIL (P1-2)** | Remove raw query `detail` from staff analytics (`recent_actions`) or restrict to aggregate counts only, unless explicitly disclosed and consented. |
| 1.3 | **PII & Secret Redaction in Logs / Telemetry** | `log_redaction.py` is installed at app boot (`factory.py:69, 82`); `user_traffic._scrub_detail()` redacts emails and `sk-`/`eyJ`/`Bearer` tokens (`user_traffic.py:20-21, 72-76`). | **PASS (Partial)** | Extend redaction regexes to Indian mobile numbers and UEM student enrollment/roll numbers before campus rollout. |
| 1.4 | **Right to Delete (`DELETE /api/chat/history`)** | `routes/chat.py:546-569` clears `user_traffic` on **only the single Vercel serverless instance** handling the request and deletes from local SQLite `completed_quiz`. It does **not** invoke Supabase `s5_research_rpc('delete_user_data')` (`20261118000000:618-625`), nor does it delete Supabase `archipelago_runtime_quota` / `student_completed_quizzes` / `s5_runs`. | **FAIL (P1-2)** | Wire an authenticated self-service deletion endpoint to `s5_research_rpc('delete_user_data')` + Supabase runtime tables, and document exact retention TTLs. |
| 1.5 | **Research Run Owner Isolation** | `s5_runs` is stored in private schema `research_intelligence` (`20261118000000:140-145`) and owner-scoped on `/runs/<id>`, `/graph`, `/xlsx`, `/preview`. **However**, `GET /api/research/intelligence/runs/<id>/dossier` falls back to `manager=True` (`research_intelligence.py:344-345`). | **FAIL (P0-2)** | Remove the `manager=True` fallback in `intelligence_dossier()` so students/faculty can only read their own runs. |
| 1.6 | **Private Cache Headers on Authenticated Responses** | `middleware.py:320-323`, `analytics.py:187-193`, `research_intelligence.py:175-181`, `research_intake.py:84-93` set `Cache-Control: private, no-store` and `Vary: Authorization, Cookie`. | **PASS** | Retain in CI regression tests. |
| 1.7 | **Explicit Retention Schedule & Automated Purge** | No automated retention TTL/cron purge exists for `research_intelligence.s5_runs`, `s5_events`, `s5_monitor_history`, `archipelago_runtime_quota_events`, or `research_processing_jobs`. | **FAIL (P1-2)** | Define UEM-approved retention periods (e.g., 90 days for quota events, semester-end purge for student runs) and implement scheduled DB cleanup. |
| 1.8 | **Student Account Offboarding / Role Revocation** | Accounts live in Supabase Auth + `public.profiles` (`20260916_000001_auth_roles.sql:12-19`). No institutional SSO/IdP sync or automated graduation deprovisioning exists. | **FAIL (P1-3)** | Define semester-based roster reconciliation or integrate institutional SSO before campus-wide onboarding. |

## 2. Source License Boundaries (Pearson, HuggingFace, Open-Access)

| Source Class | Current Repo Mechanism | Verified Boundary / Risk | Status |
|---|---|---|---|
| **Pearson eLibrary (`ebooks.elibrary.in.pearson.com`)** | `remote_cache.py:122-151` strips `subscription_id` from `public_book()` and links users to `/open/<book_id>?page=N` -> `pearson-handoff.html` (or `direct=1` redirect to Pearson's own authenticated reader). No Pearson full-text PDF scraping is performed in `host_inference`. | Must confirm with Pearson/UEM Library that metadata/TOC indexing and deep-linking to `#book/{id}/page/{n}` comply with UEM's institutional license agreement. | **CONDITIONAL (Vendor Review)** |
| **Private HuggingFace Dataset (`Prataykarali/Library_books`)** | `reader.py:25-26, 176-249` streams PDFs using server-side `HF_TOKEN`. | **P0-1**: `/pdfs/<doc_path>` bypasses authentication and rate limiting, exposing private dataset PDFs to the public internet! Furthermore, a formal copyright/license provenance audit of every file in `Prataykarali/Library_books` is required before serving to campus students. | **FAIL (P0-1 + License Audit)** |
| **Open-Access Scholarly APIs (OpenAlex, CrossRef, arXiv, Semantic Scholar)** | Metadata-first discovery (`research_intake.py`, `research_intelligence.py`); `WEB_FETCH_POLICY.md` enforces default-deny allowlist, `robots.txt`, no credentials, 1s rate spacing. | Compliant for metadata/abstracts when `ARCHIPELAGO_FETCH_ALLOWLIST` is enforced. | **PASS** |
| **Withdrawn / Expired Titles** | `host_inference/engine/withdrawal.py` filters withdrawn `doc_id`s from citations and emits provider-neutral notices. | `withdrawn_documents()` (`withdrawal.py:27-38`) imports `archipelago.resolver.source_lifecycle.load_ledger` which reads local `data/source_lifecycle.json`; on Vercel serverless, if `data/source_lifecycle.json` is absent or stale, withdrawal checks silently degrade to `set()` (no withdrawals enforced). | **WARN (P1)** — Sync withdrawal ledger via Supabase Storage alongside `okf_graph.json`. |

## 3. Koha OPAC Live-vs-Snapshot Freshness & Ingestion Consent Workflows

| Dimension | Verified Repo Implementation | Campus Pilot Assessment & Required Gate |
|---|---|---|
| **Live OPAC Target** | `https://uemk-opac.l2c2.co.in` (`/cgi-bin/koha/opac-search.pl`, `/cgi-bin/koha/opac-detail.pl?biblionumber=N`) in `host_inference/hostapp/koha_bridge.py:22-25` and `host_research/opac_live.py`. | **Read-only HTML parsing** — never writes to Koha, never logs in as a patron/staff user, never touches circulation PII. |
| **SSRF & Redirect Safety** | `_valid_opac_url()` (`koha_bridge.py:120-127`) enforces `https://uemk-opac.l2c2.co.in/cgi-bin/koha/opac-*`, `allow_redirects=False` with manual hop validation (max 3), 3s timeout, 2MB response cap. | **PASS** — Strong transport safety. |
| **Live vs Snapshot Freshness** | `lookup_chat_library_holding()` (`koha_bridge.py:493-530`) attempts live OPAC first (`source_mode: "LIVE_OPAC"`, `checked_at`), falling back to Supabase `koha_catalog_snapshot.json` (`source_mode: "KOHA_EXPORT_SNAPSHOT"`, `snapshot_updated_at`, `stale: True`). `GET /api/library/koha` serves the dated snapshot (300s warm cache). | **Conditional**: UI and chat must prominently display snapshot age when `source_mode == "KOHA_EXPORT_SNAPSHOT"`, and UEM Library / L2C2 must approve live query rate limits from Vercel IPs to prevent accidental OPAC throttling or IP blocking. |
| **Librarian Ingestion & Approval Workflow** | 1. Hosted uploads (`POST /api/ingest`) are disabled by default (`ARCHIPELAGO_INGESTION_ENABLED=0`, `ingest.py:32-38`) and restricted to `LIBRARIAN_ROLES`.<br>2. Staging review (`GET /api/academic-automation/review/<job_id>`) requires `LIBRARIAN_ROLES` and rejects `local-dev-token` (`analytics.py:321-333`).<br>3. Final graph sign-off (`POST .../decision`, `analytics.py:335-372`) requires matching `review_digest` and intentionally returns `409 workstation_required` so immutable Kùzu graph publication only executes on the local library workstation.<br>4. Scheduled campus page intake (`research_schedule.py:37-42`) crawls public `uem.edu.in` / `iem.edu.in` sitemaps daily at `03:00 UTC` via `CRON_SECRET`. | **Required before Campus GO**:<br>- Written UEM IT approval for automated daily crawling of `uem.edu.in` / `iem.edu.in` sitemaps.<br>- Documented librarian SOP for local workstation staging sign-off, rollback, and takedown (`SOURCE_LIFECYCLE.md`).<br>- Written consent from UEM Central Library for any Koha ODS export upload (`POST /api/library/import`). |
