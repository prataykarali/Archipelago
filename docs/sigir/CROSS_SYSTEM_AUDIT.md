## Verdict Semantics (D7.1 Correction)

> [!IMPORTANT]
> **BLOCKED_BY_AUTH ≠ PASS.** BLOCKED_BY_AUTH probes confirm that an auth gate
> correctly fires for anonymous callers. They do NOT demonstrate end-to-end functional
> success. Only PASS probes demonstrate reachable, functioning service endpoints.

| Verdict | Meaning |
|---------|---------|
| **PASS** | HTTP status in expected set; no unexpected auth block. |
| **FAIL** | Unexpected HTTP status, including unexpected 401/403. |
| **BLOCKED_BY_AUTH** | 401/403 on a probe with `expect_auth_block=True`. Gate confirmed; NOT a functional PASS. |
| **UNVERIFIED** | Connection error or timeout. |

## 2. What the Probes DO and DO NOT Establish

### Established (PASS probes)
- Production server is reachable and responds to public endpoints.
- Library snapshot (`stale: true`) is served with correct disclosure.
- Live Koha OPAC returns valid institutional catalog records.
- Scholarly APIs (Crossref, OpenAlex, arXiv) function with graceful degradation.
- DOI resolution chain is live.
- Pearson eLibrary handoff origin is reachable.
- Security boundaries (dotfiles, internal databases) are correctly blocked.

### NOT Established by this Automated Probe Suite
- **Authenticated chat workflow** — login → Transformer query → citation → PDF reader.
  Auth gates are confirmed to fire; the full flow requires live browser session with valid credentials.
- **Research persistence and workbook export** — topic save → revisit → Excel export.
  Guarded endpoints return 401 to anonymous callers as designed.
- **Pearson in-reader page verification** — institutional subscription required.

> [!WARNING]
> The D7.0 audit report incorrectly counted BLOCKED_BY_AUTH probes as contributing to
> end-to-end functional success. D7.1 corrects this. The 14 PASS probes establish
> reachability of public/external endpoints only.
